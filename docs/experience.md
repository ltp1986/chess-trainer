# 国际象棋习题训练系统 - 项目经验总结

## 1. 项目概述

本项目是一个国际象棋习题训练系统，核心功能包括：
1. 读取PGN棋谱文件
2. 使用Stockfish引擎分析失误
3. 生成针对性训练习题
4. 前端走棋验证

开发周期：2026年4月

---

## 2. 核心问题与解决方案

### 2.1 索引错位问题

**问题描述**：习题生成时，FEN与实际步数不对应，回合判断错误。

**根本原因**：
```python
# 原始代码：先记录状态，再走棋
boards.append(board.copy())  # 记录走棋前状态
board.push(mv)               # 走棋
```

**解决方案**：
```python
# 修复后：先走棋，再记录状态
board.push(mv)               # 走棋
boards.append(board.copy())  # 记录走棋后状态
```

**经验教训**：
- 数组索引与实际步骤的对应关系需要清晰定义
- 建议在代码中添加注释说明索引含义
- 编写单元测试验证索引逻辑

### 2.2 引擎返回结果不稳定

**问题描述**：引擎分析结果偶尔缺少`score`键，导致API 500错误。

**解决方案**：
```python
# 安全访问
score_info = res_before.get("score")
if score_info is None:
    # 处理异常情况
```

**经验教训**：
- 外部API返回结果需要进行空值检查
- 引擎分析可能因超时或资源问题返回不完整结果
- 添加try-except捕获异常

### 2.3 回合判断错误

**问题描述**：习题回合直接根据败方设置，与实际局面不符。

**解决方案**：
```python
# 根据实际局面判断回合
turn = "white" if boards[i].turn == chess.WHITE else "black"
```

**经验教训**：
- 业务逻辑与数据逻辑要分离
- 败方是筛选条件，不是回合判断依据
- 回合必须根据FEN动态计算

## 3. 技术难点与突破

### 3.1 python-chess库使用

**难点**：理解`chess.Board`对象的状态变化机制

**解决方案**：
- 深入阅读python-chess官方文档
- 编写调试脚本跟踪每步状态变化
- 理解FEN字符串各部分含义

### 3.2 Stockfish引擎集成

**难点**：引擎初始化、配置和结果解析

**解决方案**：
- 使用`chess.engine.SimpleEngine.popen_uci()`启动引擎
- 配置合适的Threads和Hash参数
- 正确处理分析结果中的score和pv字段

### 3.3 前后端数据同步

**难点**：确保前端棋盘状态与后端一致

**解决方案**：
- 统一使用FEN字符串传递状态
- 每次走棋后重新同步状态
- 添加状态验证机制
